In the context of recording decisions on parallel branches and in parallel sessions, facing ID collisions without coordination, we decided for `<keyword>-<6 random hex>` and neglected sequential numbers, sequence plus branch plus author, and a hash of the title, to achieve collision-free short IDs, accepting IDs that carry no order.

## Context
Two branches numbering decisions sequentially pick the same next number. IDs also appear in code comments and every index line, so length costs tokens.

## Decision
The keyword comes from the index's Domains list, so the folder sorts by domain. The hex comes from `openssl rand -hex 3`, or `od` on `/dev/urandom` where openssl is missing.

## Rejected
- Sequential numbers: collide across branches.
- Sequence plus branch name plus git author: branch names mean nothing after merge, author names are published in public repos, and both lengthen every reference.
- `git hash-object` of the title: an apostrophe in the title breaks shell quoting.

## Consequences
Order comes from the `date` field. A collision, if one ever happens, shows up as a git conflict on the file name and in `/adr audit`.
