In the context of keeping a project's decisions for later agent sessions, facing the token cost of finding one record, we decided for one file per record in `.adr/`, named by its ID, and neglected range-sharded files, a single log file and `.claude/decisions.md`, to achieve single-read lookup without merge conflicts for any agent, accepting many small files.

## Context
Agents need the exact record behind a decision without searching or reading unrelated records. The location must work for any LLM, in cloud sessions that have only the repository, and stay readable by a human.

## Decision
Each record is `.adr/<ID>.md`. The folder is dot-prefixed because the records support the project rather than form part of it, as `.gitignore` does. Markdown with a YAML header, so people and agents read it without tools.

## Rejected
- Range-sharded files (`infra_m-n.md`) with a mapping in the index: needs sequential IDs, conflicts when branches append to the same shard, and costs a lookup to find the file.
- A single log file: grows without bound and must be read in full.
- `.claude/decisions.md`: tied to one vendor.
- A retrieval tool: with the path equal to the ID, reading the file is already minimal.

## Consequences
Repo-wide searches that skip dot-folders miss `.adr/`, so instructions name the folder explicitly.
